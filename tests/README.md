# تست‌های سبک رگرسیون — شبیه‌ساز کشور

> همهٔ این تست‌ها با پایتون خالص و بدون Godot اجرا می‌شوند (هر کدام کمتر از چند ثانیه) و
> **قبل از هر کامیت باید سبز باشند**. در سندباکس Godot نصب نمی‌شود؛ بیلد واقعی فقط در
> GitHub Actions انجام می‌گیرد.

## اجرای همه

```bash
cd /home/user/game
for t in tests/*.py; do python3 "$t" || break; done
```

## فهرست تست‌ها

| تست | قراردادی که پایش می‌کند |
|---|---|
| `validate_engine_version.py` | نسخهٔ Godot پروژه با نسخهٔ CI یکی باشد |
| `validate_engine_contracts.py` | قراردادهای موتور/فرمان/رویداد (`SUPPORTED_COMMANDS`، ساختار state) |
| `validate_ui_architecture.py` | معماری UI موبایلی: شبیه‌سازی بدون فریز فریم، نقشهٔ کم‌جزئیات متحرک، اسکرول لمسی و پینچ‌زوم |
| `validate_country_data.py` | سلامت دادهٔ کشورها (جغرافیا/جمعیت/اقتصاد پایه) |
| `validate_country_maps.py` | انسجام نقشهٔ کشورها با دادهٔ کشور |
| `validate_world_map.py` | سلامت نقشهٔ جهان و همسایگی‌ها |
| `validate_state_keys.py` | **قرارداد کلیدهای متقاطع**: هر کلید نوشته‌شده در `state` باید مصرف‌کننده داشته باشد (خوانندهٔ متقاطع، دفترداری درون‌فایلی، نمایش پویای UI یا فهرست سفید موجّه) + قرارداد سخت برای کلیدهای حیاتی زنجیرهٔ اثر |
| `validate_budget_chain.py` | زنجیرهٔ بودجه ۱۰مرحله‌ای: هر ریال از تخصیص تا اثر و نمایش |

## قواعد

- تست‌ها فقط‌خواندنی‌اند: هیچ‌کدام فایل بازی را تغییر نمی‌دهند.
- اگر تستی به دلیل بازسازی عمدی معماری باید به‌روز شود، در همان کامیت و با توجیه در پیام
  کامیت انجام شود؛ فروکاستن آستانه برای سبزشدن ممنوع است.
- فهرست سفید `validate_state_keys.py` فقط برای الگوهای دفترداری اثبات‌پذیر است
  (مثل `last_*`، `prev_*`، مهرهای قالب `export_tick/export_version`) و هر افزودنی باید
  در کامنت همان فایل توجیه شود.
