# تست‌های سبک رگرسیون — شبیه‌ساز کشور

> همهٔ این تست‌ها با پایتون خالص و بدون Godot اجرا می‌شوند (هر کدام کمتر از چند ثانیه) و
> **قبل از هر کامیت باید سبز باشند**. در سندباکس Godot نصب نمی‌شود؛ بیلد واقعی فقط در
> GitHub Actions انجام می‌گیرد.

## اجرای همه

```bash
cd /home/user/game
for t in tests/*.py; do python3 "$t" || break; done
```

## فهرست تست‌ها

| تست | قراردادی که پایش می‌کند |
|---|---|
| `validate_engine_version.py` | نسخهٔ Godot پروژه با نسخهٔ CI یکی باشد |
| `validate_engine_contracts.py` | قراردادهای موتور/فرمان/رویداد (`SUPPORTED_COMMANDS`، ساختار state) |
| `validate_ui_architecture.py` | معماری UI موبایلی: شبیه‌سازی بدون فریز فریم، نقشهٔ کم‌جزئیات متحرک، اسکرول لمسی و پینچ‌زوم |
| `validate_country_data.py` | سلامت دادهٔ کشورها (جغرافیا/جمعیت/اقتصاد پایه) |
| `validate_country_maps.py` | انسجام نقشهٔ کشورها با دادهٔ کشور |
| `validate_world_map.py` | سلامت نقشهٔ جهان و همسایگی‌ها |
| `sim_longrun.py` | **آینهٔ عددی بلندمدت**: بازتولید معادلات روزانهٔ هسته (اقتصاد/جمعیت/سیاست/سلامت/آموزش/رفاه/بانک مرکزی/انرژی/سکونتگاه/تجارت و تراز پرداخت‌ها) در پایتون خام؛ ۱۰ سال مجازی از نقطهٔ شروع بدون اقدام بازیکن + ۶ سناریو (شوک جنگ، انبساطی/انقباضی، تحریم طولانی، محاصرهٔ اقتصادی + کاهش ارزش، بحران تخلیهٔ ذخایر ارزی + مداخله، همه‌گیری با موج قوسی + کارزار واکسن و بازیابی). شکست = چسبیدن به clamp، انفجار/فرورفت، دیفلشن مزمن، انفجار تراز/ذخایر یا بی‌پایداری تعادل |
| `validate_latches.py` | **قرارداد latch/cooldown**: هر کلید `last_*` که در گارد زمانی خوانده می‌شود باید نوشتهٔ واقعی هم‌ساعت (turn/tick) داشته باشد؛ تناقض ساعت و latch یتیم (فقط init) خطاست + فهرست سفید موجّه |
| `validate_state_keys.py` | **قرارداد کلیدهای متقاطع**: هر کلید نوشته‌شده در `state` باید مصرف‌کننده داشته باشد (خوانندهٔ متقاطع، دفترداری درون‌فایلی، نمایش پویای UI یا فهرست سفید موجّه) + قرارداد سخت برای کلیدهای حیاتی زنجیرهٔ اثر |
| `validate_budget_chain.py` | زنجیرهٔ بودجه ۱۰مرحله‌ای: هر ریال از تخصیص تا اثر و نمایش |
| `validate_budget_levers.py` | **ممیزی اهرم‌های بودجه**: هر ۱۰ ردیف budget_allocations باید خوانندهٔ بودجه‌محور واقعی داشته باشد + مالکیت یکتا: فقط economy_system حق نویسندگی government_revenue/spending را دارد (سایر سیستم‌ها از کانال نرخ ماهانه استفاده می‌کنند) |
| `validate_orphan_wiring.py` | **قرارداد سیم‌کشی کلیدهای یتیم** (بازرسی ۱۴۰۵): کانال بودجهٔ ترانزیت/رویالتی (نویسنده ↔ مصرف‌کنندهٔ economy)، مالکیت یکتای سطح exports/imports/balance با trade_system (تشخیص receiver + استثنای شوک گذرا)، latch کرش بورس (`last_crash` خوانده شود)، مصرف map_network در trade/tourism، و پاک‌سازی کلیدهای مردهٔ init |
| `validate_ai_policies.py` | **قرارداد زنجیرهٔ AI→سیاست**: هر شناسهٔ سیاستی که مشاوران AI با `create_policy_change` توصیه می‌کنند باید در `data/policies.json` موجود باشد، و هر مسیر اثر رجیستری باید به کلید عددی واقعی state اشاره کند (ممیزی ۱۴۰۵: ۵۵ توصیهٔ مرده احیا شد) |
| `validate_gdp_channel.py` | **قرارداد مالکیت یکتای سطح GDP** (ممیزی ۱۴۰۵): اثر مداوم بخش‌ها فقط از کانال `economy.sector_boosts` (نرخ سالانه، بازنویسی، سقف تکی ۵٪/کلی ۱۰٪) عبور می‌کند؛ نویسهٔ مستقیم `gdp` فقط برای مالک (economy) یا شوک گذرا/NPC و در سقف بودجهٔ پین‌شدهٔ هر فایل (pestle — فقط کم می‌شود) |
| `audit_gdp_writers.py` | پویشگر کمکی (همیشه موفق): طبقه‌بندی و برآورد بزرگی سالانهٔ همهٔ نویسه‌های `gdp` — ابزار برنامه‌ریزی مهاجرت دورهای بعد، نه گیت CI |
| `audit_state_arrays.py` | پویشگر کمکی (همیشه موفق): برگ‌کلیدهای append‌شوندهٔ state و الگوی مهارشان (trim/filter/سقف/کران طراحی) — نخستین پویش: همه مهاردار، بدون نشت |

## قواعد

- تست‌ها فقط‌خواندنی‌اند: هیچ‌کدام فایل بازی را تغییر نمی‌دهند.
- اگر تستی به دلیل بازسازی عمدی معماری باید به‌روز شود، در همان کامیت و با توجیه در پیام
  کامیت انجام شود؛ فروکاستن آستانه برای سبزشدن ممنوع است.
- فهرست سفید `validate_state_keys.py` فقط برای الگوهای دفترداری اثبات‌پذیر است
  (مثل `last_*`، `prev_*`، مهرهای قالب `export_tick/export_version`) و هر افزودنی باید
  در کامنت همان فایل توجیه شود.
